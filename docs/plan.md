# 진행 계획

먼저 한 사람이 최소 버전까지 만들고, 그다음 팀원에게 나눈다.

## 최소 버전 (아는 101종이 앱에서 동작)
| 순서 | 만들 것 | 끝나면 되는 것 |
|---|---|---|
| 1 | `knowledge/judge.py` | 후보 3개 + 확률 + 내 알레르기 → 🔴🟡⚪, 1단계/2단계 분기 |
| 2 | `backend/main.py` (FastAPI `/analyze`) | 사진 보내면 판정 결과 JSON |
| 3 | `frontend/index.html` | 폰 브라우저에서 사진 찍고 결과 카드 보기 |

판정 기준(EDA v2 임시값): 레시피 비율 60% 이상 주의 / 20~60% 확인 필요 / 20% 미만 해당 없음 / 레시피 30개 미만 정보 부족.
후보 합치기: 확신 애매하면 상위 3개 중 가장 높은 비율로 (보수적으로) 판정.

## 확장
| 순서 | 만들 것 | 끝나면 되는 것 |
|---|---|---|
| 4 | 검색용 레시피 파일(1M_Final 제목·재료·영양) + `knowledge/search.py` | 처음 보는 음식도 이름으로 레시피 찾아 판정 |
| 5 | `llm/` 이름 추정 · 재료 추정 · 설명 | 이름 몰라도 판정 + "왜요?" |
| 6 | 기준 실험 노트북 | "아는 음식" 기준선(최대 확률 vs energy 점수, TPR95), 1등만/3개 합치기 기준을 val로 결정 |
| 7 | `build_table.py` Colab 실행 | food_table.csv에 영양 중앙값 칸 추가 |
| 8 | 학과 서버 배포 | 실제 주소로 접속 |
| 9 | 알레르기 정답지 (20~30종 사람 확인) | 경고 놓침(FN) 비율 — 발표용 숫자 |

## 나중에 팀원에게 나눌 덩어리
