# 왜 CLIP인가 (팀원 설명·발표용)

> **한 줄:** 처음 보는 음식은 **이름을 모르는 게 정상**이다. CLIP은 이름을 거치지 않고 **사진 → 비슷한 레시피 글**로 바로 가는 유일한 방법이고,
> 찾아온 레시피가 그대로 **판정 근거**가 된다. 그리고 우리 데이터로 **학습시켜 성능을 올릴 수 있는** 부분이라 딥러닝 수업의 핵심 기여가 된다.

---

## 1. 풀어야 하는 문제부터
분류 모델(ConvNeXt)은 **101종 안에서만** 답한다. 해외여행에서 만나는 음식은 대부분 그 밖이다 → 2단계가 필요하다.

2단계가 해야 하는 일:
```
처음 보는 음식 사진 ──?──> 알레르기 19항목 비율 (1단계와 같은 모양)
```
비율은 **레시피 통계**에서만 나온다 (육수·소스·반죽 속 재료는 사진에 안 보이니까).
그러니까 진짜 문제는 **"사진 한 장 → 그 음식의 레시피들"을 어떻게 찾느냐**다.

## 2. 가능한 방법 4개와 탈락 이유
| 방법 | 어떻게 | 왜 안 되나 |
|---|---|---|
| **A. 분류 모델을 175종으로 늘리기** | 클래스를 더 넣어 다시 학습 | 여전히 **목록 밖은 못 본다** (176번째 음식에서 또 막힘). 음식 추가마다 재학습. 한식·희귀 음식은 학습 사진이 10장도 안 됨 |
| **B. LLM이 이름 추정 → 이름으로 레시피 글자 검색** | GPT 같은 모델에 "이거 뭐야?" | 연결 고리가 **이름 하나**라 끊기기 쉽다: 이름이 틀리면 틀린 레시피, 표기가 다르면(`khao soi` vs `curry noodle soup`) 0건. 같은 사진도 답이 매번 다름. 우리 데이터로 학습 불가 → 딥러닝 기여 없음 |
| **C. 비슷한 사진 찾기** (사진 ↔ 사진) | 레시피 사진들과 사진끼리 비교 | **사진이 있는 레시피만** 찾을 수 있다. 사진 주소가 살아 있는 건 약 67%, 한식은 10장 미만 → 레시피 글은 있는데 사진이 없는 음식은 영영 못 찾음 |
| **D. 사진에서 바로 알레르기 맞히기** | 사진 → 19항목 다중 분류 | 안 보이는 재료를 사진에서 맞히라는 것. 정답 라벨도 없고, **근거가 안 남는다** ("왜 새우?"에 답 못 함) |
| ✅ **CLIP 검색** (사진 ↔ 레시피 **글**) | 사진과 레시피 글을 같은 공간의 벡터로 → 가장 가까운 레시피 K개 | 아래 3장 |

## 3. CLIP이 맞는 이유 6가지
1. **이름이 필요 없다.** 사진 벡터와 레시피 글 벡터를 바로 비교한다. "음식 이름 몰라도 된다"는 앱 취지 그대로.
2. **목록이 닫혀 있지 않다.** 검색 대상은 레시피 **글**이다. 새 음식 추가 = 레시피 글을 벡터로 바꿔 목록에 넣기. **재학습 없음.** 사진이 없는 음식도 글만 있으면 찾힌다 (C의 약점 해결).
3. **찾아온 게 곧 근거다 (RAG의 "R").** 가까운 레시피 30개 → 그중 몇 개에 새우가 들어가는지 → 1단계와 **같은 모양의 비율 줄** → **같은 룰**로 판정.
   설명도 "비슷한 레시피 30개 중 24개에 새우 육수"처럼 근거가 붙는다. LLM은 이 근거를 말로 풀기만 한다.
4. **불확실함을 정직하게 다룬다.** 답 하나를 고르는 게 아니라 레시피 여러 개의 **비율**이라, 애매하면 비율이 중간값(→ `확인 필요`)으로 나온다. "없다"고 단정하지 않는 우리 원칙과 맞다.
5. **우리 데이터로 학습시킬 수 있다 = 학습 ②.** 기본 CLIP은 웹 사진 + 짧은 설명글로 배웠다. 우리 글은 "제목 + 재료 목록"이라 모양이 다르다.
   레시피 사진 ↔ 제목+재료 짝 수만 개로 **대조 학습(파인튜닝)** → 전/후 숫자로 효과를 보인다. B(LLM)는 이게 불가능하다.
6. **서버에서 가볍다.** 레시피 글 벡터는 미리 계산해 두고(`index_emb.npy`), 요청마다 사진 1장만 벡터로 바꿔 곱하면 끝. 검색 자체는 1ms 안쪽 (04 7번에서 CPU 시간 측정).

## 4. 그럼 ConvNeXt는 왜 남기나
| | ConvNeXt (학습 ①) | CLIP (학습 ②) |
|---|---|---|
| 질문 | "101종 중 **뭐야**?" | "이 사진과 **비슷한 레시피**는?" |
| 강점 | 아는 음식은 빠르고 정확 (test top-1 0.89) | 목록 밖도 레시피로 연결 |
| 비유 | 메뉴 101개 외운 직원 | 요리책 뒤지는 사서 |

**싼 모델 먼저, 모를 때만 넓게** (cascade). 아는 음식까지 CLIP에 맡길지는 04 7번 숫자(정확도·CPU 시간)로 정한다.

## 5. 전체 흐름에서 CLIP 자리
```
사진 → ConvNeXt (101종, 확신도)
          │ 확신 높음 → [1단계] food_table에서 그 음식 줄 ───────────────┐
          │ 확신 낮음 (처음 보는 음식)                                     ▼
          ▼                                                   [룰 판정] 🔴🟡⚪ (항상 같은 규칙)
     CLIP: 사진 → 가까운 레시피 30개 → 19항목 비율 ──────────────────────▲
          + LLM 이름 추정으로 교차 확인 (CLIP과 다르면 '확인 필요' 쪽으로)
          │
     LLM 설명: 찾아온 레시피를 근거로 쉬운 말 ("왜요?")
```
LLM은 빠지는 게 아니라 **판정 밖에서 보조**(교차 확인 + 설명)로 바뀐다.

## 6. 숫자로 보여줄 것 (노트북 04)
| 비교 | 보여주는 것 | 기대 |
|---|---|---|
| **학습 전 vs 후 CLIP** — 처음 보는 음식 20종 (학습에 사진 한 장도 안 씀) | 학습이 외우기가 아니라 **일반화**됐다 | 레시피검색 top1·단계일치 ↑, **주의놓침 ↓** |
| 이름 맞히기 vs 레시피 검색 | 이름만 비교하는 기본 사용법보다 레시피를 직접 찾는 게 낫다 | 레시피 검색이 알레르기 오차 ↓ |
| ConvNeXt vs CLIP (Food-101) | 아는 음식은 ConvNeXt가 맡는 근거 | ConvNeXt 정확도·속도 우위 |

**주의놓침**(정답은 `주의`인데 `해당 없음`으로 나온 비율)이 우리 앱에서 제일 중요한 숫자다. 정확도보다 이걸 앞에 둔다.

**추가하면 가장 강한 근거 (LLM 정해지면):** 같은 처음 보는 음식 20종에서 **B(LLM 이름 → 글자 검색)** vs **CLIP 검색**의 단계일치·주의놓침 비교.
"이름을 거치면 이만큼 끊기고, CLIP은 안 끊긴다"를 숫자로 보여줄 수 있다. (담당: 유라님 `guess_name` + 중현)

## 7. 한계 (먼저 말하면 질문에 강해진다)
| 한계 | 대응 |
|---|---|
| 겉모습이 비슷한데 재료가 다른 음식 (예: 카레류) | 1등 하나가 아니라 레시피 30개의 비율 → 섞이면 `확인 필요`. LLM 교차 확인 |
| 레시피 사이트 사진 ↔ 식당·여행 사진 분위기 차이 | 학습 때 자르기·뒤집기 증강. 시연 사진으로 따로 확인 |
| 한식은 사진·레시피가 적음 | 30장 미만은 학습·평가에서 빼고 검색 대상으로만. 레시피 30개 미만은 `정보 부족` |
| 같은 음식의 다른 레시피도 학습 때 "틀린 짝"으로 취급 | 제목·재료가 달라서 영향 작음. 노트북에 한계로 명시 |

## 8. 자주 받을 질문
- **"그냥 GPT한테 사진 주고 알레르기 물어보면 되잖아?"** → 지어낼 수 있고, 근거가 안 남고, 같은 사진에 답이 매번 다르다. 알레르기는 놓치면 위험해서 **근거 있는 일정한 규칙**이 판정해야 한다. LLM 직접 판정과의 놓침 비교는 준영님 평가에서 숫자로 보인다.
- **"분류 모델 클래스를 늘리면 되지 않아?"** → 몇 개를 늘려도 목록 밖은 못 본다. CLIP은 레시피 글만 넣으면 된다.
- **"CLIP이 틀리면?"** → 답 하나가 아니라 30개 레시피 비율이라 틀려도 크게 안 튀고, 애매하면 `확인 필요`. "안전하다"는 어떤 경우에도 말하지 않는다.
- **"학습한 게 뭐야? 그냥 가져다 쓴 거 아냐?"** → 레시피 사진 ↔ 제목+재료 짝으로 대조 학습했고, **학습에 안 쓴 음식**에서 전/후를 비교한다.

## 발표용 세 문장
1. 처음 보는 음식은 이름을 모른다. 이름을 거치는 방법(LLM 추정, 분류 확장)은 이름에서 끊긴다.
2. 그래서 사진에서 **레시피 글로 바로** 가는 CLIP 검색기를 우리 레시피 데이터로 학습시켰다.
3. 찾아온 레시피가 그대로 판정 근거가 되고, 판정은 1단계와 같은 법 기준 룰이 한다.
