# 찍먹 🍽️ — 음식 사진 한 장으로 "나한테 위험한지" 알려주는 웹 앱

해외여행에서 처음 보는 음식을 찍으면, 내 알레르기 기준으로 위험한지와 영양 정보를 알려준다.
음식 이름을 몰라도 된다.

👉 **처음 보는 팀원은 [`docs/진행상황.md`](docs/진행상황.md)부터** (쉬운 설명 · 지금까지 한 것 · 다음 할 일)

## 사용자 입장
```
① 내 알레르기 고르기 (예: 땅콩, 새우)
② 음식 사진 찍기
③ 결과:  🔴 새우 주의   ⚪ 땅콩 거의 없음   칼로리 450 · 나트륨 높음
         [왜요?] "보통 새우 육수를 써요..."   [가게에 물어보기] "Does this contain shrimp?"
```

## 우리 내부 흐름
```
사진 ─> [학습 ① 분류 모델] 무슨 음식? (후보 3개 + 확신도)
           │
     아는 음식인가? ── 예 ──> [1단계 룰베이스] 미리 만든 표(food_table)에서 찾기 ──┐
           │                                                                     ▼
           아니오                                                     [판정] 내 알레르기 기준 🔴🟡⚪
           ▼                                                                     ▲
     [2단계 RAG] [학습 ② CLIP] 사진과 비슷한 레시피 찾기 (+LLM 이름 추정으로 교차 확인) → 같은 규칙으로 계산 ──┘
                 (레시피도 없으면 LLM이 재료 추정 → 같은 규칙, '추정' 표시)
           │
     [설명] LLM이 찾아온 표·레시피를 근거로 쉬운 말 설명
```

**학습(딥러닝) 파트는 2개**: ① 분류 모델(ConvNeXt, 아는 음식) ② CLIP 검색기(처음 보는 음식 → 레시피)

**원칙**
- 판정은 항상 같은 규칙(`knowledge/rules.py`)이 한다. LLM은 이름 추정·재료 추정·설명만 한다.
- 1단계와 2단계는 같은 모양의 "알레르기 비율 줄"(19항목 + 레시피 수 + 출처)을 만든다 → 판정 함수 하나로 처리.
- 어떤 화면에서도 "안전하다"고 표시하지 않는다. 레시피 30개 미만은 `정보 부족`, LLM 추정은 `추정` 표시.

| 폴더 | 내용 | 상태 |
|---|---|---|
| `frontend/` | `index.html` 웹 화면: 알레르기 선택(기억됨), 카메라, 결과 카드 | 1단계 결과 표시됨 |
| `backend/` | `main.py` FastAPI: `POST /analyze`(사진 + 알레르기 → 판정 JSON), `GET /allergens` | 1단계 연결됨, 설명은 LLM 연결 후 |
| `modeling/` | `model.py` 예측(후보 3개 + 확률), `classes.txt` 101종 목록, `weights/best.pt`(깃 제외) | 예측 코드 있음 |
| `knowledge/` | 룰베이스: `rules.py` 규칙, `build_table.py` 표 만들기, `candidates.csv` 새 음식 후보 74종, `food_table.csv` 결과표, `lookup.py` 표 찾기, `judge.py` 판정·1/2단계 분기 | 1단계 완료, 2단계 검색 예정 |
| `llm/` | `guess.py` 이름·재료 추정, `explain.py` 설명 | 빈 함수 |
| `evaluation/` | `정답지.csv` 알레르기 정답지 (사람 확인) | 틀만 있음 |
| `AGENTS.md` | AI 코딩 도구용 규칙·데이터 형식·함수 모양 (`CLAUDE.md`가 불러옴) | 있음 |
| `notebooks/` | `01` EDA·전처리(알레르기·나트륨), `02` 새 음식 후보 집계, `03` 표 확장(175종)·사진 수집, `04` 학습 ② CLIP 파인튜닝 | 03 완료, 04 실행 전 |
| `docs/plan.md` | 단계별 할 일 | 있음 |
| `docs/역할분담.md` | 팀원별 담당 (한솔·중현·유라·준영) | 있음 |

## 실행
```bash
pip install -r requirements.txt
# 드라이브 찍먹_실험기록/best/convnext_tiny/best.pt → modeling/weights/best.pt
uvicorn backend.main:app --reload
```
http://localhost:8000 이 앱 화면(폰은 같은 와이파이에서 `http://PC주소:8000`, 카메라는 https 배포 후), http://localhost:8000/docs 는 API 시험 화면.
LLM API 키·서버 계정은 `.env`에만 둔다 (gitignore 됨). 절대 커밋하지 않는다.
